# 下个场景启动提示词

已安装技能时，在新场景对话中粘贴下面内容，并附上需求文档与原型图。只需补齐工程位置、需求文件和主参考；已有规范中的内容可以注明“沿用工程”，不用重复填写。

```text
使用 $reference-scene-builder，实际制作或精修以下三维场景。

工程位置：【工程路径】
需求文档：【文件路径或附件】
主参考图：【文件名；注明地面、航拍或其他机位】
辅助参考：【可选，说明每张图用于结构、材质还是光照】
场景与本轮范围：【场景名称；需要完成的区域或重点】
技术栈与目标环境：【沿用工程；新项目则按需求确定】

目标是尽可能接近主参考图的构图、形体、空间层次、材质和光照，并保留已有游览功能。界面和菜单使用简体中文。质量优先，不以全部程序化为目标，也不要擅自降低核心画质或更换技术栈。

先阅读工程规范和需求，检查现有场景、资产、材质、灯光、相机及发布方式。区分已确认约束、可观察的参考关系和制作假设；缺少真实地理数据时不要宣称实景精准还原，在已授权美术近似范围内推进。

先建立固定对照机位，记录位置、朝向、FOV和画幅；对齐后再判断是否需要改变地形或道路尺寸。保留原机位和已经认可的布局，用同一三维世界支持不同视角。

按画面贡献确定资产制作方法。先完成整体轮廓、前中远层次和大色块，再精修一个决定画质的代表性资产或小区域。可以使用本地 Blender Python 实际建模和资产处理；如果形体方法不适用，应换方法，不要用不断增加噪声、面数或重复物体代替还原。

在代表性小样中核对真实几何、材质和接地，再尽早接入目标引擎与发布环境。统一天空、主光、环境光与反射。重复资产优先共享几何/实例，并检查导出体积和运行可见性。

每轮说明主要差距、修改依据和实际结果，不要只汇报生成数量。遇到确实无法解决的关键资产、数据或工具阻塞，停止依赖工作并告诉我需要什么；已经获得的授权不要反复确认，能够独立推进的部分继续完成。

按工程规范完成编译、资源检查和必要运行验证；本项目不编写或保留单元测试、测试框架、临时截图和检查报告。保留源码、可编辑模型、原始贴图、来源和必要重建资料。

最后确认我打开的页面或程序实际加载了本轮产物，说明完成项、剩余视觉差距和验证范围。视觉验收由我判定。请现在开始实施，推进到可验证的结果或明确阻塞。
```

## 已有场景的简短续做指令

```text
使用 $reference-scene-builder。以【主参考文件】为目标继续精修【工程/场景】。
保留当前技术栈、游览功能与已认可布局。先核对固定机位，再找出当前画面最显著的差距，实际修改最关键的一组资产或水光关系。用小样证明方法有效再扩展；遇到真正阻塞停止依赖工作并说明所需帮助。最后核对目标环境实际运行版本，保留制作源并清理临时预览，不自行宣告人工验收通过。
```

## 在没有安装技能的环境中使用

将本技能整个 `reference-scene-builder` 文件夹带到新环境的个人技能目录，或提供 `SKILL.md` 和相关 `references/` 文件，并明确要求读取。单独复制 `$reference-scene-builder` 这一名称不会携带技能内容；未加载技能时也可直接使用上面的完整流程提示词。
