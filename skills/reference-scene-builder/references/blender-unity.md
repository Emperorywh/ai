# Blender → Unity → 浏览器的接入经验

仅在对应技术栈使用。下列 SC01 事实解释风险，不要求新项目沿用 Unity 6000.6.6f1、URP 17.6.0、WebGPU、PAL、具体目录或参数。先读新项目规范；其他引擎保留相同的源资产、导出和运行核验原则。

## 源资产与导出契约

保留 `.blend`、制作参数/脚本、原始贴图和来源记录；生产构建显式消费 FBX、RAW 等导出文件，不把运行 Blender 变成日常引擎构建的隐藏依赖。手工精修后的源文件不得被重建脚本无提示覆盖；需要重做时保留可恢复基线，避免无限复制无用版本。

资产清单至少能对应：源文件和修订、导出文件及哈希、单位与轴向、世界基准、对象/材质标识、几何与 UV/遮罩约定、贴图色彩空间和用途、依赖及来源。只记录用于重建和核对的事实，不把检查结果永久写成“已验收”。

坐标变换只应用一次。用非对称校准对象或有明确方向的标志检查 X/Y/Z、朝向、1米长度和地面基准，结合实际导入器输出求映射，不能只抄理论轴交换。源模型、Terrain、相机、碰撞和植被都用同一个归一化空间。

FBX 导出前保持一致的最终三角划分，确认法线、材质槽、UV 和顶点色随导出保留；在源文件中独立重开，再导回一次检查。法线/切线的重算法或导入模式以实际材质需求为准，不无差别重算全部。

连续地表若用分区 Terrain，应从同一高程场采样，明确 RAW 分辨率、位深、端序、底高与高度范围；相邻块共享边界样本。改变地形后，岸线、道路贴地、植被根部及碰撞须重新核对。

## 材质数据不能只靠肉眼猜

- Base Color、法线、粗糙度、遮罩各自指定色彩空间和通道语义；核对法线图的 OpenGL/DirectX 约定、Unity 导入类型及是否需要翻转。
- Blender 工作色、Unity 材质接口、自定义 Shader uniform 和顶点色不一定采用相同转换路径。记录“输入是什么、在哪转换一次”，防止遗漏或重复 Gamma/Linear 转换；不要规定所有颜色一律调用同一转换函数。
- 雪岩遮罩用连续权重过渡时，确认 FBX 导入后的 `COLOR` 与源色属性语义一致。不能把点级权重丢失后的一色结果误判成灯光问题。
- UV0 可承载米制纹理尺度，UV1 的用途按项目声明；没有烘焙需求时不要为了形式强制指定 lightmap UV。大型景观避免每个网格各自归一化导致纹理尺寸跳变。
- Blender Workbench 的材质色和腔隙效果不等于节点材质渲染。实际材质预览也不能替代 Unity Shader 与目标图形后端观察。

## 重复资产先考虑数据共享

SC01 曾将5,130株树展开后合并成空间块，区域B约524万三角形，共享资源文件约705MB、Brotli后约212.5MB；这是一个具体版本的资源观察，不是通用预算。暴露的问题是几何重复，不能据此得出“树不能多”或“必须降画质”。

合并网格可能减少对象或部分绘制开销，却不等于共享顶点数据；仅启用材质 instancing 也不会把不同的合并 Mesh 自动还原成实例。应优先验证少量共享树型与每株变换能否完整跨过导出/导入链路，可使用预制体或实例清单重建。核对实际共享 Mesh 数、导出体积、剔除、阴影、下载与驻留，而不只看场景对象数。

先用代表性林块或其他重复资产估算，必要时使用适合观察距离的 LOD/表示。保留近景质量；任何已确认核心画质的调整都按当前授权处理。

## 迭代和构建分层

| 变化 | 优先验证 | 何时需要发布 |
| --- | --- | --- |
| 需求、来源、说明 | 文档一致性和链接 | 通常不需要引擎构建 |
| 相机、环境参数 | 同一配置、材质/方向、运行默认视角 | 验证实际目标画面时 |
| 模型、Terrain、材质导入 | 小样重开/导回、尺度、遮罩、接缝 | 扩展前的代表性资产接入，以及最终产物 |
| Shader、运行代码或后端相关依赖 | 编译、目标管线和代表场景 | 尽早验证真实目标后端 |
| 仅宿主网页 | 对应前端构建/检查 | 按宿主与引擎集成规则，不无故重做全部资产 |

若已有可验证的窄刷新入口，仅机位/环境变化不应重新生成整个模型、Terrain和植被；入口要能确认几何未变。没有现成入口时，先评估是否值得添加，避免为一次调整引入复杂工具链。

批处理与编辑器不能同时写同一工程。Windows 启动后台辅助进程使用隐藏窗口；沿用项目构建脚本和明确日志路径。进程还在工作、CPU仍在计算或Brotli仍压缩时，不把长时间无新日志当作失败；结合进程、退出码和阶段判断。

保留正常迭代所需缓存，按用户清理要求在适当时机删除临时产物。不要为了提速绕过清单、混用上一版资源或手改内部构建图。SC01 的压缩候选复用尝试仅通过编译、未验证实际复用，最终已撤回，不能作为推荐实现。

## 发布到“当前页面”的证据链

使用项目既有的完整构建和发布保护，失败不覆盖当前可用站点；不自行改压缩方式、后端或升级引擎。对于 SC01 的 WebGL 构建目标名，实际图形后端仍必须读取运行时确认，不能据名称推断 WebGL 渲染。

用当前发布清单、实际服务根目录、HTTP返回版本和运行日志确认新资源已生效；留意旧进程、旧端口、浏览器缓存、未刷新页面和只更新源资产。页面连不上时先检查服务及产物，不重复启动多份服务。

代表性检查覆盖默认机位、相关旧机位、资源切换和受改动影响的游览功能，检查编译/控制台错误。模型完整、场景加载、控制可用、视觉目标和性能分别报告；不能以“启动成功”包含所有结论。

记录实际观察环境、版本、分辨率和质量设置。单次加载时间、构建耗时、资源大小和运行内存是不同指标；有测量方法才报告相应结果，不将一次就绪观察包装成稳定性能。
